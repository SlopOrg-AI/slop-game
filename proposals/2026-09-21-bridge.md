# Proposal — the bridge: how Cowork and Claude Code work in concert

**Produced by:** Tech (Claude Code), 2026-09-21 · **Targets:** `bridge/` (new, provisional), `leads/README.md`, both briefs · **Status:** `PROPOSED`, and **half-built** — `bridge/tech.md` is live so there is something to handshake with. Chief of Staff is setting up the handshake in parallel on the owner's instruction; **if its shape differs, its shape wins and Tech moves.** The protocol matters, the path does not.

**Owner:** *"we need a bridge and way for cc and workspace to work together in concert. CoS on cowork and tech on cc."*

---

## 1. What actually separates the two surfaces

Not goodwill, and not the rules — four structural facts:

| | Cowork (Chief of Staff) | Claude Code (Tech) |
|---|---|---|
| The working tree | writes it directly | writes it directly |
| **Git** | **none** — cannot commit, cannot read the log, cannot see what changed or when | all of it |
| Messaging | not reachable from Tech | can message other Claude Code sessions |
| Memory between sessions | none | none |

So: **Tech can see the record and cannot author the board. Chief of Staff authors the board and cannot see the record.** Each holds exactly what the other is missing. That is the whole reason a bridge is worth building rather than a habit of being careful.

Tonight's three failures all sit in that gap. The D5.41 collision: two sessions read the same next-free number because neither could see the other's in-flight work. The decision-ID reformat that blinded three guard rails: the log's shape changed and the tooling's owner was not told. The 27-item queue in `leads/systems/tech.md`: a channel one side invented and the other never knew to read.

## 2. The protocol — four rules

1. **Each side writes exactly one bridge file, and only its own.** `bridge/tech.md`, `bridge/cos.md`. Never the other's — the same rule that governs briefs (D5.27) and the one Tech got wrong tonight.
2. **Read the other's file at session open, before the board and before the inbox.** This is the part that failed: a drop box nobody is obliged to open is not a channel.
3. **Answer in your own file.** An item is closed when the *sender* sees the disposition and clears it from its own list. Nobody marks anything done in someone else's file.
4. **Update your file at session close**, even to say nothing changed. Silence should mean "not run", never "nothing to report".

A third surface (the art execution agent) gets `bridge/art.md` on the same terms. Nothing about this is Tech↔CoS specific.

## 3. What each side owes the other — the part that is not symmetric

The files are symmetric; the content is not, because the deficits are not.

**Tech → Chief of Staff — the git view it cannot get any other way.** Maintained in `bridge/tech.md` at every session close:

| Field | Why Chief of Staff needs it |
|---|---|
| Last commit: hash, subject, time | Its only way to know where the record stands |
| Tree state: clean, or dirty with whose work | It cannot run `git status`. Its own uncommitted work has sat 40+ minutes unseen |
| **Next free D-number** | D5.42 makes numbering Tech's. Every collision tonight came from reading a stale board |
| Committed on your behalf | It has no log to check what Tech swept or typed |
| Guard rails in force | So a refused commit is legible rather than mysterious |
| Flags for you | Items needing its ruling, one line each |

**Chief of Staff → Tech — the authoring view Tech must not produce.** In `bridge/cos.md`:

| Field | Why Tech needs it |
|---|---|
| Board rows to transcribe, verbatim | D5.38: Tech types what Chief of Staff authors |
| Rulings that change mechanism | The ID reformat needed to reach Tech *before* it landed, not after |
| Dispositions on Tech's flags | acted · declined · needs the owner |
| What it is about to touch | A one-line heads-up prevents two surfaces writing one file |

## 4. The handshake proper

A handshake is two parties confirming they can hear each other, not one party announcing.

1. Chief of Staff reads `bridge/tech.md`, writes `bridge/cos.md` with one disposition — anything — and closes its session.
2. Tech reads it, clears the matching item from its own list, and records that the round trip completed.
3. **From then on the bridge is presumed live**, and a session that does not update its file is a fault worth noticing.

Until step 2 has happened once, the bridge is a proposal and not a channel. Tonight's 27-item queue is exactly what an unconfirmed channel looks like after five hours.

## 5. What this does not fix

- **Concurrent writes to one tree.** The bridge reduces surprise; it does not prevent two sessions editing one file. The structural fix is one clone per surface (`2026-09-20-two-machine-migration.md`, `2026-09-20-execution-agents.md` §4.2), and it needs Cowork to have git, which today it does not.
- **Staleness.** Both files are written at session close and read at session open. If Chief of Staff works for an hour, Tech's state line is an hour old. Anything Tech states there is *as of that commit*, and it says so.
- **Honesty.** Same limit as the session report: a bridge file is a claim. Git is the evidence, and only one side can read it.
